# НА КОНТРОЛІ · БЕТА 1

Задачі, етапи та повтори в мінімалістичному PWA українською. Працює на iPhone, Android і комп’ютері. Особистий простір зберігається локально; для команд можна підключити власний Firebase.

**Це перша бета.** Командний режим поки перевіряйте на вигаданих даних. Придатність для військових або службових відомостей не підтверджена. Поточні обмеження описані в додатку та [архітектурі команд](docs/TEAMS-ARCHITECTURE.md).

## Опублікувати сайт

1. Розпакуйте **`NaKontroli-GitHub.zip`**. Сам ZIP завантажувати в репозиторій не потрібно.
2. Створіть публічний репозиторій GitHub із головною гілкою **`main`**. Завантажте **вміст архіву в корінь**, де лежить `index.html`, а не всю зовнішню папку. Включіть приховані **`.github/workflows/pages.yml`** та **`.nojekyll`**. На macOS приховані файли показує `⌘⇧.`.
3. Відкрийте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Відкрийте **Actions → Publish GitHub Pages → Run workflow** для `main`. Дочекайтеся успішного завершення. Адреса сайту з’явиться в **Settings → Pages**.
5. Відкрийте HTTPS-сайт і натисніть **«Інструкція»**. У додатку є покрокове налаштування простору, встановлення, власної бази, користувачів і команд.

Workflow уже включений. Він публікує лише дозволені файли сайту, без адміністративних скриптів або документації розробника. Node.js і Firebase CLI для завантаження файлів на GitHub не потрібні. [Офіційна інструкція GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## Один сайт — різні бази

**Користувачам не потрібно копіювати ваш репозиторій.** Вони відкривають ту саму адресу, створюють свій локальний простір і за бажанням підключають базу власного адміністратора. Firebase-конфіг вводиться в додатку та зберігається в просторі; спільного конфігу, акаунта чи бази в репозиторії немає.

Для однієї команди всі використовують конфіг того самого Firebase-проєкту та окремі видані логіни. Люди з іншим проєктом працюють зі своєю базою. Адреса сайту або знання Firebase-конфігу самі по собі доступу до команд не дають: потрібні акаунт, дозвіл `USERS` і погоджене членство.

Google-акаунт потрібний адміністратору **на сайті Firebase Console**. У самому додатку учасник вводить **логін і тимчасовий пароль**, після чого встановлює власний. Паролі перевіряє Firebase Authentication; у Firestore паролів та їхніх хешів немає.

Не додавайте в репозиторій персональні JSON-копії, паролі, service account або інші адміністративні ключі. Для налаштування бази користуйтеся вбудованою інструкцією; її текстова версія — [FIREBASE-SETUP.md](docs/FIREBASE-SETUP.md).

## Встановлення та збереження даних

- **iPhone:** Safari → «Поділитися» → «На початковий екран».
- **Android:** Chrome → меню → «Установити додаток» / «Додати на головний екран».

Перший раз дочекайтеся повного завантаження з інтернетом. Після цього особисті задачі працюють офлайн. Усі бібліотеки вже включені у файли проєкту; CDN не потрібен.

Регулярно експортуйте зашифровану копію через **«Простір»**. Очищення браузера або зміна адреси сайту може позбавити доступу до локальних даних. Відновлення забутого PIN немає; 4 цифри не захищають викрадену копію від тривалого офлайн-перебору. Закритий додаток не гарантує нагадувань у фоні.

## Службові інструменти

Для звичайного використання вони не потрібні. Адміністратор із Node.js 24 може виконати `npm ci` і користуватися `npm run accounts -- --help` для створення користувачів або скидання пароля зі збереженням UID. Налаштування адміністративного доступу описане в інструкції; цей інструмент не публікується на сайті.

Локальна перевірка готової збірки:

```sh
node scripts/package-pages.mjs
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Відкрийте `http://127.0.0.1:4173/`. `file://` не підходить для PWA. Для повторного створення чистого архіву потрібні Node.js 24, npm і Python 3: `npm run build:release`. Для відтворення локального Firebase SDK: `npm ci`, потім `npm run build:firebase`.

Архів містить лише застосунок, потрібні інструкції та службові інструменти. Тестів із демонстраційними даними, емуляторів, старого сервера, логів і встановлених залежностей у ньому немає. Підсумки перевірок та їхні межі — [TEST-REPORT.md](docs/TEST-REPORT.md).
